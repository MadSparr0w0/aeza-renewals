# Aéza · Регулярные платежи

Приложение для регулярных расходов нескольких изолированных команд: аренды, подписок, серверов и других ежемесячных платежей. Участник создаёт свои расходы и управляет ими, администратор добавляет участников своей команды. Личный кабинет доступен на сайте и в Telegram; автоматические напоминания поступают в выбранные группы каждой команды.

Модуль хранит введённые вручную суммы, сроки и отметки. Он не списывает деньги и не проверяет банковскую оплату. Бренд Aéza, аватар и username [@aezainkeep_bot](https://t.me/aezainkeep_bot) сохранены, но расходы не ограничены услугами Aéza и не требуют её биллинга.

## Как устроена работа

В одном экземпляре приложения могут работать несколько команд. У каждой команды собственный администратор, участники, платежи, приглашения, журнал действий и до 20 выбранных групп Telegram.

- Обычный участник видит только свои расходы, периоды, итоги и историю. Он создаёт, меняет и прекращает свои серии, отмечает оплату и исправляет её дату. Чужие записи недоступны и через API.
- Администратор видит расходы только своей команды, управляет её участниками и может создать расход от имени любого её участника. Первый администратор задаётся окружением и создаёт новых отдельных администраторов через раздел «Команда» или `POST /api/v1/admins`. Он видит их имена и логины, но не их финансовые данные и группы.
- Администратор либо создаёт участника с заданным паролем, либо выдаёт одноразовую ссылку на 72 часа. По ссылке участник сам задаёт пароль и получает новую сессию. Участник и отдельный администратор могут позднее сменить свой пароль, указав текущий; после смены их сессии отзываются и нужен новый вход.
- Аккаунт сайта связывается с Telegram через явное подтверждение. После привязки можно входить на сайт без ввода пароля через кнопку в боте. В личке доступны платежи, история и сводка с теми же правами: участник видит своё, администратор — свою команду. Создание и отметки оплаты остаются на сайте.
- Автоуведомления поступают только в выбранные группы. Администратор использует `/chats`, выбирает группу штатной кнопкой Telegram и подтверждает публикацию имени владельца, названия, суммы, валюты и срока. Каждая группа отключается отдельно; сообщения разных команд не смешиваются.
- Большие списки загружаются страницами по 30 записей. Поиск, сортировка и фильтры выполняются в SQL; итоги учитывают весь набор, календарь получает агрегаты по дням. Экспорт CSV в интерфейсе явно относится к текущей странице.

Срок каждого месяца и отметка оплаты независимы. История сохраняется, просрочка начинается со следующего дня после срока. Для 31-го числа используется последний день короткого месяца, затем исходное число восстанавливается. RUB, USD и EUR учитываются отдельно, без конвертации. Поддерживается ежемесячное повторение.

## Создать отдельную команду

1. Войдите конфигурационным администратором из `.env` и откройте «Команда».
2. Нажмите «Создать администратора», задайте уникальный логин и пароль длиной от 12 символов. Передайте их новому администратору безопасным способом.
3. Новый администратор входит в собственную сессию, добавляет участников и подключает свою Telegram-группу в настройках. Адрес веб-панели и бот общие, данные и получатели уведомлений разделены.

При обновлении старой базы все существующие пользователи, платежи, приглашения, журнал и подключённая группа относятся к первой команде. Идентификаторы пользователей и действующие сессии сохраняются. Перед обновлением работающей установки сделайте резервную копию SQLite и окружения.

## Подключить Telegram и несколько групп

1. Войдите на сайт по логину и паролю → «Настройки» → «Привязать Telegram». Откройте бота и подтвердите действие, затем вернитесь в исходный браузер. Альтернатива: `/login` в личке бота → ссылка на сайт → вход и явное согласие на привязку.
2. Для следующих входов выберите на сайте «Войти через Telegram». Подтвердите действие в личке и вернитесь в тот же браузер.
3. Администратор добавляет бота в нужные группы с правом отправки и открывает `/chats` в личке. Нажимает «Выбрать группу», выбирает её и отдельно подтверждает включение уведомлений. Повторяет для других групп.
4. Список и отключение отдельных групп доступны в боте и настройках сайта.

Привязка не создаёт аккаунт и не повышает роль. Доступ выдаётся существующему участнику. [Подробности входа и бота](docs/telegram-sso.md), [загрузка частями и проверка на 50 000 записях](docs/scaling.md).

### Резервный мастер подключения одной группы

Мастер заменяет текущие группы только своей команды. Для добавления нескольких используйте `/chats`.

1. Администратор входит в веб-панель и создаёт код подключения со сроком 10 минут.
2. Добавляет бота в корпоративную группу с правом отправлять сообщения.
3. Администратор этой Telegram-группы отправляет `/connect@aezainkeep_bot CODE` с полученным кодом.
4. Бот проверяет тип чата и статус отправителя в группе. Найденная группа появляется в веб-панели.
5. Администратор приложения проверяет её и подтверждает подключение. Только после этого разрешены уведомления.

Открытие бота по ссылке, `/start`, старый личный чат или прежний `TELEGRAM_CHAT_ID` сами по себе не подключают группу. Получатель фиксируется в задании outbox: смена текущей группы не должна незаметно перенаправлять уже назначенное сообщение. Точные переходы при переподключении проверяются при приёмке новой версии.

Токен бота хранится только на сервере в `TELEGRAM_BOT_TOKEN`. Подробности и проверка доступа: [Telegram](docs/telegram.md).

## Локальный запуск в Windows

Нужны Python 3.12+ и Node.js 22 с npm для сборки интерфейса. Откройте PowerShell в каталоге `invoice-keeper`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/init_env.py
```

Инициализатор спросит пароль администратора и необязательный пароль демонстрационного участника `demo`. Используйте собственные пароли длиной не менее 12 символов. По умолчанию логин администратора - `admin`; другой задаётся `--admin-username`. Скрипт создаёт локальный `.env` с scrypt-хешем администратора и случайным `APP_SECRET`, открытый пароль администратора не сохраняет. Существующий файл не перезаписывается. `.env`, пароли, база и резервные копии в публичную поставку не входят.

Соберите frontend:

```powershell
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

Если проверенная поставка содержит готовый `frontend/dist` и менять интерфейс не требуется, установка Node.js и повторная сборка необязательны.

Для новой учебной базы выполните seed. Названия и суммы условны. При существующих данных seed не используется как способ сброса базы.

```powershell
.\.venv\Scripts\python.exe -m backend.seed
.\scripts\run.ps1 -NoWorker -NoBot
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Войдите собственным администратором, создайте участников или приглашения. Seed новой пустой базы добавляет условные аренду, подписки и другие расходы с владельцами admin/demo. Прежние записи не переименовываются автоматически.

После настройки токена и перед подключением группы запустите все процессы:

```powershell
.\scripts\run.ps1
```

`-NoWorker` отключает отправку напоминаний, `-NoBot` - обработчик Telegram. Runner останавливает созданные им процессы при завершении. Логи находятся в локальном `data/`. Если политика PowerShell запрещает запуск скрипта, используйте отдельные терминалы:

```powershell
# API
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

```powershell
# Напоминания
.\.venv\Scripts\python.exe -m backend.worker
```

```powershell
# Подключение Telegram-группы
.\.venv\Scripts\python.exe -m backend.telegram_bot
```

## Linux, macOS и Docker

Для Linux/macOS используйте `python3 -m venv .venv` и `.venv/bin/python` вместо Windows-пути. Инициализация, seed и имена Python-модулей те же. Frontend собирается командами `npm ci` и `npm run build` в `frontend`.

Docker Compose собирает frontend внутри образа; Node.js на хосте не нужен. Сначала создайте собственный `.env` через `scripts/init_env.py`.

```bash
docker compose build
docker compose run --rm api python -m backend.seed
docker compose up -d
docker compose logs -f api worker bot
```

Сервисы `api`, `worker`, `bot` используют постоянный том `invoice-data`; API публикуется на `127.0.0.1:8000`. Обычный `docker compose down` сохраняет данные. Вариант `down -v` удаляет том и не подходит для штатного перезапуска.

## Окружение

| Параметр | Назначение |
|---|---|
| `ADMIN_USERNAME`, `ADMIN_PASSWORD_HASH` | Конфигурационный администратор и его scrypt-хеш |
| `APP_SECRET` | Случайный серверный секрет, минимум 32 символа |
| `APP_ORIGIN` | Точный адрес интерфейса без пути, локально `http://127.0.0.1:8000` |
| `APP_ALLOWED_ORIGINS` | Дополнительные точные origin при необходимости |
| `TIMEZONE` | Общий деловой часовой пояс, по умолчанию `Europe/Moscow` |
| `DATABASE_PATH` | Постоянный файл SQLite на локальном диске |
| `COOKIE_SECURE` | `false` для локального HTTP, `true` для публичного HTTPS |
| `SESSION_HOURS` | Срок сессии, по умолчанию 12 часов |
| `TELEGRAM_BOT_TOKEN` | Серверный токен текущего бота |
| `DEMO_USER_PASSWORD` | Необязательный пароль участника `demo`, только для seed |

Группа хранится в базе и подключается подтверждаемым веб-сценарием; legacy-параметр TELEGRAM_CHAT_ID не является её авторизацией. TELEGRAM_BOT_USERNAME задаёт username для служебной команды и ссылки, по умолчанию aezainkeep_bot.

Секреты нельзя передавать в `VITE_*`: они попадают в JavaScript браузера. Значения паролей не передаются через аргументы командной строки. Для автоматизации инициализатор поддерживает имена переменных `--admin-password-env IK_ADMIN_PASSWORD --demo-password-env IK_DEMO_PASSWORD`.

## API

API - способ общения страницы с сервером. Нажатие «Оплачено» вызывает запрос; сервер проверяет сессию, владельца и данные, изменяет один период и возвращает результат. Пользователю не требуется вручную вызывать API для обычной работы.

После входа откройте [Swagger](http://127.0.0.1:8000/api/v1/docs) на том же адресе. Получите `csrf_token` через `GET /api/v1/auth/me` и укажите его в «Авторизация → csrfHeader» для изменений. Cookie браузер отправляет автоматически. API модуля и внешний Telegram Bot API - разные интерфейсы; API биллинга Aéza проекту не требуется.

Обязательные маршруты кейса сохраняют `/api/v1`. Добавлены контракт владельца `owner_id`, `owner_name`, `can_manage`, приглашения `/invitations` и смена пароля `/auth/password`. Контракты описаны в руководстве и текущем OpenAPI. Дополнительные методы дополняют обязательные маршруты исходного кейса.

## Проверка и обслуживание

Команды и результаты релиза фиксируются в [qa.md](docs/qa.md). Новая приёмка должна доказать права владельца прямыми API-запросами, оба способа добавления участников, одноразовость приглашений, отзыв сессий при смене пароля и подтверждаемое подключение группы. Исторические результаты старой версии не заменяют эти проверки.

Для резервной копии используйте SQLite backup API либо остановите API, worker и poller перед переносом базы. При активном WAL недостаточно произвольно скопировать только `.db`. Сохраняйте владельцев, приглашения, привязку группы, outbox и offset вместе с остальными данными. Перед переносом токена остановите старый poller и worker: lease одной SQLite не координирует независимые базы на двух хостах.

Публичный адрес требует HTTPS reverse proxy, точного `APP_ORIGIN` и `COOKIE_SECURE=true`. Неподтверждённая отправка Telegram получает `unknown` и не повторяется автоматически: первое сообщение могло дойти. Отметка `sent` означает подтверждение Bot API, а не прочтение всеми участниками группы.
