# Aéza · Контроль продлений

Работающий брендированный тестовый модуль для учёта продлений серверов, хостинга, доменов и других инфраструктурных расходов. Сроки и суммы вводятся вручную. Панель хранит историю, независимые ежемесячные периоды, фактические даты оплаты и просрочку; Telegram напоминает за три дня и показывает сводку. RUB, USD и EUR учитываются отдельно.

Оплата выполняется в [официальном кабинете Aéza](https://my.aeza.ru/). Отметка «Оплачено» в модуле фиксирует введённый пользователем факт: она не проводит платёж и не продлевает услугу у провайдера. Фактический баланс, списания и состояние услуги модуль не получает. Вход использует отдельные учётные записи модуля, без SSO с кабинетом Aéza. Администратор задаётся окружением.

Стек: React + TypeScript + Vite, FastAPI, SQLite, отдельный worker напоминаний и обработчик Telegram-команд. Собранный frontend отдаёт FastAPI. Типографика следует брендбуку Aéza: локальные Exo 2 и Inter. Текущий интерфейс тёмный, со светлым текстом и единым оранжевым акцентом `#E97C35`; повторяющиеся информационные блоки убраны. Исходная палитра брендбука, включая голубой `#4CC6F1`, отдельно сохранена в документации и не подменяется палитрой этой версии. Правила и источник фирменного знака описаны в [документе об айдентике](docs/aeza-brand.md).

Поставка сохраняет обязательный контракт кейса «Invoice Keeper»: роли, историю, ежемесячность и маршруты `/api/v1`. Техническое имя каталога `invoice-keeper`, имя SQLite-файла и команды сборки сохранены для совместимости. Пользовательское название продукта — «Aéza · Контроль продлений»; Telegram-бот — [@aezainkeep_bot](https://t.me/aezainkeep_bot).

Текущая проверенная сборка: `index-CW5-7-ui.js` / `index-DbInrObd.css`. Сайт и бот обновлены на тестовом стенде; результаты проверок, трёх подтверждённых Telegram-доставок и активных служб приведены в [отчёте QA](docs/qa.md).

Архив поставки содержит готовый `frontend/dist`. При запуске этой сборки без изменения интерфейса шаг установки Node.js и сборки frontend можно пропустить. Локальные `.env`, база и пароли в архив не включены: на новом компьютере выполните инициализацию окружения и seed.

## Локальный запуск в Windows

Требуются Python 3.12+ и Node.js 22 LTS с npm. Откройте PowerShell в каталоге `invoice-keeper`.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/init_env.py
```

Скрипт использует логин администратора `admin` и попросит пароли через скрытый ввод. Введите собственный пароль администратора и отдельный пароль для пользователя `demo`, каждый не короче 12 символов. Другой логин можно задать флагом `--admin-username`. Скрипт создаёт локальный `.env` с хешем пароля администратора и случайным `APP_SECRET`. Пароль администратора запомните: открытым текстом в файле он не хранится. Не заменяйте хеш в `.env` обычным паролем. Существующий `.env` скрипт сохраняет без изменений.

Соберите интерфейс:

```powershell
Set-Location frontend
npm ci
npm run build
Set-Location ..
```

Загрузите демонстрационные данные и запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m backend.seed
.\scripts\run.ps1
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Войдите администратором `admin` с введённым паролем. Обычный демонстрационный пользователь имеет логин `demo` и пароль `DEMO_USER_PASSWORD`, заданный локально при инициализации. Если пропустить его пароль клавишей Enter или использовать `--no-demo`, seed добавит только платежи; пользователя можно создать в панели позже. Повторный seed сохраняет уже существующие записи.

При пустой базе seed добавляет условные инфраструктурные расходы. Их названия и цены служат демонстрации и не являются тарифами или счетами Aéza. Существующие записи автоматически не переименовываются и не перезаписываются.

`run.ps1` запускает API, worker напоминаний и обработчик Telegram-команд, а при завершении останавливает созданные им фоновые процессы. Флаги `-NoWorker` и `-NoBot` независимо отключают соответствующий процесс. Логи находятся в `data/worker.stdout.log`, `worker.stderr.log`, `bot.stdout.log` и `bot.stderr.log`. Если PowerShell блокирует локальный скрипт политикой выполнения, используйте отдельные терминалы:

```powershell
# Терминал 1 — API
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --no-access-log --no-proxy-headers
```

```powershell
# Терминал 2 — worker
.\.venv\Scripts\python.exe -m backend.worker
```

```powershell
# Терминал 3 — команды Telegram
.\.venv\Scripts\python.exe -m backend.telegram_bot
```

## Запуск через Docker Compose

Нужны Docker Engine/Desktop с Compose v2 и Python 3.12+ для безопасной локальной инициализации `.env`. Node.js на хосте не нужен: frontend собирается в образе. Для нового `.env` выполните `python scripts/init_env.py` в Windows или `python3 scripts/init_env.py` в Linux/macOS. Если файл уже создан, повторять инициализацию не нужно. Этот скрипт использует только стандартную библиотеку Python.

```bash
docker compose build
docker compose run --rm api python -m backend.seed
docker compose up -d
docker compose logs -f api worker bot
```

Адрес: [http://127.0.0.1:8000](http://127.0.0.1:8000). Сервисы `api`, `worker` и `bot` используют один постоянный том `invoice-data`. `docker compose down` останавливает приложение и сохраняет данные; `docker compose down -v` удаляет том с данными, поэтому не используйте `-v` для обычного перезапуска.

Образ содержит сборку frontend и Python-приложение, работает от отдельного пользователя без root. Сервисы имеют файловую систему только для чтения, кроме тома данных и `/tmp`. `.env`, база и зависимости с хоста в образ не попадают.

## Окружение и Telegram

Все параметры описаны в `.env.example`. Не отправляйте локальный `.env` в Git или третьим лицам.

| Переменная            | Назначение                                                           |
| --------------------- | -------------------------------------------------------------------- |
| `ADMIN_USERNAME`      | Логин конфигурационного администратора                               |
| `ADMIN_PASSWORD_HASH` | Хеш scrypt; создаёт `scripts/init_env.py`                            |
| `APP_SECRET`          | Случайный серверный секрет, не короче 32 символов                    |
| `APP_ORIGIN`          | Точный адрес интерфейса, локально `http://127.0.0.1:8000`            |
| `APP_ALLOWED_ORIGINS` | Дополнительные точные origin для локальной разработки, через запятую |
| `TIMEZONE`            | Единый деловой часовой пояс, по умолчанию `Europe/Moscow`            |
| `DATABASE_PATH`       | Файл SQLite; в Compose принудительно `/app/data/invoice_keeper.db`   |
| `COOKIE_SECURE`       | `false` для локального HTTP, `true` для публичного HTTPS             |
| `SESSION_HOURS`       | Срок жизни сессии, по умолчанию 12 часов                             |
| `TELEGRAM_BOT_TOKEN`  | Токен вашего бота, только на сервере                                 |
| `TELEGRAM_CHAT_ID`    | Единственный разрешённый чат для напоминаний, команд и кнопок        |
| `DEMO_USER_PASSWORD`  | Собственный пароль демопользователя; нужен только seed               |

Для реальных сообщений создайте бота через BotFather, добавьте его в тестовый чат и предоставьте право отправлять сообщения. Укажите `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, затем перезапустите API, worker и обработчик команд. Для личного чата сначала отправьте боту `/start`. Без Telegram-конфигурации приложение остаётся доступным для локальной работы, но реальной доставки нет.

Пошаговая инструкция: [подключение Telegram](docs/telegram.md). Токен сохраните локально в `.env`; передавать его в переписке не требуется.

Worker проверяет неоплаченные периоды каждые 15 секунд. За три календарных дня до срока он отправляет название, сумму, валюту и срок; добавленный позже платёж попадает в ближайшую проверку сразу. Оплаченные периоды и прекращённые регулярные платежи пропускаются. Локальный outbox предотвращает повторную постановку и повторные подтверждённые доставки. Неопределённый результат Telegram получает состояние `unknown` и требует проверки оператором; такое задание автоматически не повторяется. Подробности и запрос для диагностики описаны в [архитектуре](docs/architecture.md).

Командный бот запускается отдельно как `python -m backend.telegram_bot` и использует те же параметры Telegram. Он показывает данные только в разрешённом чате; команды из других чатов игнорируются.

| Команда           | Что показывает                                                    |
| ----------------- | ----------------------------------------------------------------- |
| `/start`, `/menu` | Меню разделов                                                     |
| `/summary`        | Итоги текущего месяца отдельно по валютам                         |
| `/payments`       | Платежи текущего месяца и их статусы                              |
| `/upcoming`       | Неоплаченные платежи от сегодня до даты через 7 дней включительно |
| `/overdue`        | Все неоплаченные периоды со сроком раньше сегодня                 |
| `/help`           | Подсказки по командам и доступу                                   |

Списки разбиты по 6 строк, кнопки переключают страницы, а в месячных разделах — ещё и месяц. Дата определяется `TIMEZONE`. Команды и кнопки служат для просмотра; отметка оплаты и управление остаются в веб-панели. Кнопка «Кабинет Aéza» открывает внешний официальный кабинет и не авторизует пользователя автоматически. Обработчик сохраняет offset обновления до ответа, поэтому после сбоя ответ может не прийти и автоматически не повторяется. Можно отправить команду снова. Подробности запуска, доступа и восстановления приведены в [инструкции Telegram](docs/telegram.md).

Тексты профиля и семь русских команд подготовлены в `assets/telegram/profile.json` и `assets/telegram/profile.md`. Аватар `assets/telegram/avatar.jpg` — неизменённый JPEG пользователя; PNG является только технической конвертацией формата. Эти файлы не содержат секретов. Проверка в Windows без чтения окружения и без сети: `.\.venv\Scripts\python.exe scripts/configure_telegram.py --expected-bot aezainkeep_bot --photo assets/telegram/avatar.jpg --dry-run`. В Linux/macOS используйте `.venv/bin/python`. Применение профиля к боту выполняется отдельно; команда и её действие описаны в [инструкции Telegram](docs/telegram.md#профиль-бота).

Секреты нельзя передавать в `VITE_*`: такие значения попадают в JavaScript браузера. Для автоматизированной инициализации поддерживаются имена переменных окружения `--admin-password-env IK_ADMIN_PASSWORD --demo-password-env IK_DEMO_PASSWORD`; значения паролей в аргументы командной строки не передаются.

## Правила учёта и права

- Администратор добавляет/прекращает учёт регулярных продлений, меняет будущие условия и управляет обычными пользователями. Его собственная учётная запись изменяется только через окружение.
- Обычный пользователь видит общий список, подтверждает/отменяет оплату конкретного периода и исправляет фактическую дату. Сервер проверяет роль независимо от UI.
- Периоды ежемесячные, история не стирается. Число 31 даёт последний день февраля, затем снова 31 марта. Просроченный период не препятствует следующему.
- Изменение названия, суммы и валюты действует с первого числа следующего месяца для неоплаченных будущих периодов. Текущий месяц, прошлое и оплаченные будущие периоды сохраняют прежние снимки. График не меняется. Если список долго не обновлялся, сервер сначала попросит обновить его, чтобы создать пропущенные периоды по старым условиям.
- В день срока просрочки нет. Для оплаченного периода просрочка зависит от фактической даты, для неоплаченного — от текущей даты в `TIMEZONE`. Отмена оплаты очищает дату.
- Итоги отображаются отдельно по RUB, USD и EUR. Конвертации валют нет.
- Прекращение учёта сохраняет историю и прекращает дальнейшие напоминания. Оно не отключает сервер, домен или подписку у провайдера. Изменение суммы в модуле не меняет тариф Aéza.

Поддерживаемая периодичность — ежемесячно. Годовые циклы в этой версии не рассчитываются; доменные расходы в демоданных показывают условную модель ежемесячного учёта. Реальные сроки и условия продления нужно сверять в официальном кабинете.

## API, проверки и документация

Обязательные endpoints имеют префикс `/api/v1`. После входа откройте [Swagger](http://127.0.0.1:8000/api/v1/docs). Статическая спецификация для передачи решения находится в `openapi.json`. Для изменяющих запросов используются сессионный cookie и `X-CSRF-Token`; токен выдаётся при входе/получении текущего пользователя. В Swagger выполните `GET /auth/me`, скопируйте `csrf_token` и укажите его в `Авторизация → csrfHeader`; cookie передаётся браузером автоматически. Данные и документация защищены авторизацией. Администратору также доступен `GET /api/v1/reminders` для диагностики доставки.

Команды автоматических проверок и фактический результат приведены в `docs/qa.md` после финальной проверки поставки. Для живой проверки Telegram нужны собственные параметры чата: подмена транспорта в тестах не подтверждает доставку во внешний сервис.

Дополнительный `PATCH /api/v1/recurring-payments/{id}` принимает все три поля `name`, `amount`, `currency` и возвращает `effective_from`. Права администратора, CSRF и Origin проверяются сервером. Для прекращённой серии, несозданных прошлых/текущих периодов или отправляемого напоминания затрагиваемого будущего периода сервер возвращает `409` без изменения данных. Изменение отражается в журнале; повтор тех же нормализованных условий не создаёт новое событие.

## Обслуживание

Останавливайте API, worker и обработчик Telegram-команд перед переносом базы. Для резервной копии активной базы используйте SQLite backup API или согласованный снимок; простое копирование `.db` при активном WAL может потерять изменения. Сохраняйте outbox и offset Telegram вместе с остальными таблицами, чтобы не повторять старые уведомления и обработанные команды после восстановления.

Для публичного доступа поставьте приложение за HTTPS reverse proxy, задайте точный `APP_ORIGIN` и `COOKIE_SECURE=true`. Подробности, ограничения одного хоста и обработка неопределённых Telegram-доставок описаны в документации. Финансовые данные, пользовательские пароли и токен бота не должны попадать в публичные логи или frontend.

Исходные скриншоты доступа к серверу, SSH-пароли, рабочий `.env` и приватные резервные копии не входят в исходный код, демонстрационные снимки и архив поставки.
