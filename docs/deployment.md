## Состав поставки

Публичная поставка включает исходники, frontend/dist, спецификацию OpenAPI, README, .env.example без секретов, демонстрационные данные, лицензии и материалы защиты. Каталог invoice-keeper и systemd-имена aeza-renewals сохраняются для совместимости.

## Один хост

Три процесса используют один локальный файл SQLite. Сетевой файловый ресурс и несколько серверов с независимыми копиями базы не поддерживаются. Для текущей модели один экземпляр соответствует одной команде и одной подтверждённой группе.

| Путь | Назначение |
|---|---|
| /opt/aeza-renewals/current | Код, .venv, готовый frontend; сервисам только чтение |
| /etc/aeza-renewals/environment | Закрытый EnvironmentFile root, 0600 |
| /var/lib/aeza-renewals | Постоянные данные сервиса, каталог 0700 |
| aeza-renewals-api.service | Внутренний Uvicorn |
| aeza-renewals-worker.service | Очередь напоминаний |
| aeza-renewals-bot.service | Служебное подключение группы |

Шаблоны и подготовка пользователя — [scripts/deploy/README.md](../scripts/deploy/README.md). В релизе не оставляют локальный .env: systemd передаёт параметры EnvironmentFile, а недоступный .env может помешать загрузке. Windows .venv на Ubuntu не переносится.

## Подготовка и обновление

1. Проверить доступ оператора, диск, срок аренды и актуальную приватную резервную копию.
2. Собрать frontend и установить зависимости на целевой платформе до запуска.
3. Создать закрытое окружение с валидным хешем admin и независимым APP_SECRET. APP_ORIGIN — точный HTTPS-origin, COOKIE_SECURE=true, DATABASE_PATH — абсолютный постоянный путь.
4. Перед обновлением сохранить согласованный снимок SQLite и остановить API, worker, poller. При активном WAL не копировать произвольно только .db.
5. Применить проверенную версию и миграцию к прежней базе; не заменять её пустой и не запускать seed как сброс.
6. Проверить количество и значения серий/периодов, владельцев, сессии, outbox, привязку группы и offset, integrity/foreign keys.
7. Запустить службы и проверить HTTPS health, вход и пользовательские сценарии.

```bash
sudo systemctl restart aeza-renewals-api.service aeza-renewals-worker.service aeza-renewals-bot.service
sudo systemctl status aeza-renewals-api.service aeza-renewals-worker.service aeza-renewals-bot.service
```

Статус active означает работающий процесс, а не успешный сценарий или доставку. Финансовые запросы, права владельца и группа проверяются отдельно. Команда не выводит закрытое окружение.

Docker Compose остаётся альтернативой с одним образом api/worker/bot и постоянным invoice-data. Обычный down сохраняет том; down -v удаляет данные. После изменения окружения контейнеры пересоздаются штатно по README.

## HTTPS и секреты

API слушает 127.0.0.1:8000; nginx принимает внешние HTTPS-запросы. Proxy перезаписывает X-Forwarded-For реальным адресом клиента и X-Forwarded-Proto фактической схемой. Uvicorn доверяет forwarded только loopback-proxy. Базу и внутренний порт не открывают наружу.

Cookie требует Secure, HttpOnly и SameSite; изменения также проверяются CSRF/Origin. Секреты не попадают в VITE_*, полный Bot API URL или логи. Оператор ограничивает доступ к EnvironmentFile и копиям.

На тестовом VPS ранее применялось временное сопоставление api.telegram.org с доступным официальным адресом при обычной проверке TLS. Это эксплуатационная мера стенда, а не отключение сертификатов и не гарантия доступности Telegram. При переносе сетевой путь проверяют заново.

## Подключение группы после установки

Одного TELEGRAM_BOT_TOKEN недостаточно для доставки. Администратор приложения генерирует код на 10 минут. Telegram-admin группы добавляет бота и выполняет /connect@aezainkeep_bot CODE. Web-admin подтверждает найденную группу. Только тогда возможны новые напоминания.

Прежний TELEGRAM_CHAT_ID не включает личный чат. Миграция group → supergroup требует новой привязки. Отключение отменяет pending/retry, sent/unknown и offset сохраняются. Получатель конкретного задания хранится в outbox.

Перед переносом токена старый poller и worker останавливают: lease общей SQLite не блокирует приложение с другой базой на втором хосте. Профиль публикуется отдельно; актуальное применение уже проверено, но оно не подключает группу и не подтверждает доставку.

## Приёмка нового экземпляра

- Закрытый финансовый API без входа, корректные cookie/CSRF/Origin.
- Два user: каждый читает и меняет только своё, admin видит всё.
- Создание admin за участника и самостоятельное создание user.
- Создание с паролем, приглашение на 72 часа, одноразовость/отзыв/истечение, fresh session.
- Смена собственного пароля с отзывом всех сессий, неизменяемость env-admin.
- Кандидат группы без web-confirm не получает данные; Telegram-admin и права бота проверяются.
- Новое сообщение с владельцем в фактически подтверждённой группе.
- Даты/валюты/история, перезапуск и отсутствие повтора подтверждённого задания.
- Передача серий удалённого участника admin, сохранение истории.
- Сборка, мобильный интерфейс, OpenAPI и воспроизводимый README.
