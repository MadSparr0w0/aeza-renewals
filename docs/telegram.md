# Telegram модуля «Aéza · Контроль продлений»

В проекте два отдельных фоновых процесса. `backend.worker` отправляет напоминания по срокам, а `backend.telegram_bot` отвечает на команды и кнопки. Они используют один токен, один разрешённый чат и общую SQLite. Просмотр в Telegram не требует открытой веб-панели. Отметки оплаты и управление выполняются в веб-панели после входа.

Для модуля выбран бот [@aezainkeep_bot](https://t.me/aezainkeep_bot) с пользовательским названием «Aéza · Контроль продлений». Это брендированный тестовый модуль с ручным учётом: название услуги, сумма, срок и факт оплаты вводятся пользователями. Бот не получает фактический баланс или состояние услуги и не выполняет оплату/продление. Кнопка «Кабинет Aéza» открывает `https://my.aeza.ru/` с отдельной авторизацией. Учётные записи и сессии модуля не являются SSO кабинета.

## Подключение

1. Если бот ещё не создан, откройте [официального @BotFather](https://t.me/BotFather), отправьте `/newbot` и выберите имя и username. BotFather выдаст токен. Для уже созданного бота используйте существующий токен.
2. В локальном `.env` задайте `TELEGRAM_BOT_TOKEN`. Не пересылайте токен, `.env` или скриншоты с ними в чат. Остальные параметры файла сохраните.
3. Выберите чат:
   - Личная переписка: откройте бота и нажмите **Запустить** или отправьте `/start`.
   - Группа: добавьте бота, разрешите отправлять сообщения и напишите `/start@username_вашего_бота`. Для обычных команд не требуется отключать режим приватности или выдавать права администратора, если сообщения разрешены настройками группы.
4. Укажите числовой ID выбранного чата в `TELEGRAM_CHAT_ID`. Его можно получить из обновления `getUpdates` после отправленной команды. Для этого остановите другие процессы, читающие обновления этого бота. Токен читайте локально на сервере; URL с токеном не вставляйте в браузер и общие логи. У групп ID часто отрицательный; минус сохраняется.

Используются существующие параметры:

```dotenv
TELEGRAM_BOT_TOKEN=токен_из_BotFather
TELEGRAM_CHAT_ID=числовой_ID_выбранного_чата
```

Это названия параметров с условными значениями. Буквальные заглушки использовать нельзя. Дополнительных секретов для командного бота не требуется.

После изменения настроек перезапустите API, worker и обработчик команд. Нативный запуск: остановите предыдущие процессы и выполните `scripts/run.ps1`. При ручном запуске в отдельных терминалах из корня проекта:

```powershell
# Напоминания
.\.venv\Scripts\python.exe -m backend.worker
```

```powershell
# Команды и кнопки
.\.venv\Scripts\python.exe -m backend.telegram_bot
```

В Linux/macOS используйте `.venv/bin/python` вместо `.\.venv\Scripts\python.exe`. API запускается по README. Выберите запуск через общий скрипт или вручную, чтобы не создавать лишние процессы. Для команд одного токена нужен один обработчик обновлений. Защита в SQLite предотвращает одновременный polling экземплярами приложения, использующими одну базу; отдельную базу или другое приложение с тем же токеном эта блокировка не контролирует.

`run.ps1` по умолчанию запускает оба фоновых процесса. Их можно независимо отключить флагами `-NoWorker` и `-NoBot`. Вывод обработчика команд записывается в `data/bot.stdout.log` и `data/bot.stderr.log`. При завершении скрипт передаёт фоновым процессам сигнал остановки через локальный marker и ждёт до 45 секунд; оставшиеся процессы завершает принудительно.

Для Docker после изменения `.env` выполните `docker compose up -d --force-recreate api worker bot`, чтобы все сервисы перечитали окружение. Логи: `docker compose logs -f api worker bot`.

## Команды и кнопки

Отправьте `/start` в подключённом чате, чтобы открыть меню.

| Команда | Результат |
|---|---|
| `/start` | Приветствие и меню разделов |
| `/menu` | Меню разделов |
| `/summary` | План, оплачено, осталось и просрочено за текущий месяц, отдельно по валютам |
| `/payments` | Раздел «Продления»: платежи текущего месяца со сроками, суммами и статусами |
| `/upcoming` | Неоплаченные платежи со сроком от сегодня до даты через 7 дней включительно |
| `/overdue` | Все неоплаченные периоды со сроком раньше сегодняшней даты |
| `/help` | Краткая справка по командам и доступу |

Даты определяются единым `TIMEZONE` сервера. RUB, USD и EUR считаются отдельно, без конвертации. Списки содержат по 6 записей на странице. Кнопки переключают страницы; в месячных разделах доступны предыдущий и следующий месяц в пределах от 2000 года до пяти лет вперёд. Нажатие кнопки обновляет исходное сообщение. Кнопки меню и обновления позволяют вернуться к разделам и запросить свежие данные.

Команды и кнопки показывают данные. Они не подтверждают оплату, не меняют её дату, не создают пользователей и не прекращают регулярные платежи. Для этих действий откройте веб-панель.

Реальная оплата выполняется в официальном кабинете Aéza; веб-панель только сохраняет ручную отметку. Прекращение учёта не отключает услугу. Периодичность модели — ежемесячно; условные деморасходы на домены не задают реальный годовой цикл регистратора. Семь имён команд сохранены для совместимости с кейсом и текущим ботом.

## Доступ

Разрешён ровно тот чат, чей ID совпадает с `TELEGRAM_CHAT_ID`. Сообщения из других чатов игнорируются; данные туда не отправляются. Для кнопок проверяется чат исходного сообщения, а в личной переписке — также совпадение отправителя с владельцем чата. Кнопки без доступного контекста чата не принимаются. Имя пользователя Telegram и переданные в кнопке параметры сами по себе не дают доступ.

Если подключена группа, просмотр разрешён её участникам: персональная веб-роль для каждой команды Telegram не проверяется. Подключайте группу, участникам которой можно показывать финансовые названия, суммы и сроки. Сам бот не даёт участникам права изменять данные через веб-API.

Частота команд и кнопок ограничена. При слишком частых нажатиях подождите несколько секунд и повторите действие.

## Напоминания и восстановление

Worker проверяет сроки каждые 15 секунд. За три календарных дня до срока он отправляет название, сумму, валюту и дату. Поздно добавленный платёж попадает в ближайшую проверку сразу. Первый запуск также обрабатывает ожидающие задания демонстрационных платежей. Оплаченные и прекращённые платежи пропускаются. Проверка токена и чтение обновлений сами по себе не отправляют напоминания.

Состояние напоминаний хранится в outbox. Подтверждённая отправка не повторяется; неоднозначный сетевой результат получает состояние `unknown` для проверки оператором. Диагностика доступна администратору через `GET /api/v1/reminders`. Подробности — в [архитектуре](architecture.md).

Обработчик команд сохраняет offset обновления в SQLite **до ответа**. Это предотвращает автоматическое повторное выполнение уже обработанной команды после перезапуска. Если процесс завершился или ответ потерялся после сохранения offset, ответ может не прийти: бот не воспроизводит его автоматически. Отправьте команду снова. Offset команд и outbox напоминаний независимы.

При отсутствии ответа проверьте оба параметра Telegram, запущенный `backend.telegram_bot`, право бота отправлять сообщения и отсутствие другого приложения, читающего тот же токен. Если уже настроен webhook, сначала согласуйте переход на polling; приложение не удаляет существующий webhook автоматически.

## Профиль бота

В `assets/telegram/profile.json` подготовлены имя «Aéza · Контроль продлений», описание тестового модуля с ручным учётом и семь команд с русскими подписями. Читаемая версия — `assets/telegram/profile.md`. Аватар `assets/telegram/avatar.jpg` — побайтная копия предоставленного пользователем JPEG 640 × 640; композиция, фон и изображение не менялись. PNG — только техническая конвертация формата. Происхождение и контрольные суммы указаны в `assets/telegram/provenance.md`. Тексты и изображения не содержат токена и ID чата. Подготовка файлов не является подтверждением их публикации: фактический результат фиксируется после применения и readback.

Проверка локальных файлов без чтения `.env` и сетевых запросов:

```powershell
.\.venv\Scripts\python.exe scripts/configure_telegram.py --expected-bot aezainkeep_bot --photo assets/telegram/avatar.jpg --dry-run
```

Применение к боту:

```powershell
.\.venv\Scripts\python.exe scripts/configure_telegram.py --expected-bot aezainkeep_bot --photo assets/telegram/avatar.jpg
```

Используйте Python из установленного окружения проекта; в Linux/macOS команда имеет вид `.venv/bin/python scripts/configure_telegram.py ...`. Если оформляете другого бота, укажите его username в `--expected-bot`. Флаг обязателен: скрипт сначала проверяет бота через `getMe` и подключённый чат через `getChat`, затем меняет профиль. Без `--photo` текущий аватар сохраняется.

Команда без `--dry-run` выполняет внешние изменения: устанавливает название и описания по умолчанию и на русском языке, список команд и кнопку меню, при переданном `--photo` — аватар. Публичный список содержит только `/start` и `/help`, а семь команд задаются для подключённого чата. После применения скрипт сверяет обе языковые версии текстов, публичные команды и команды чата, проверяет тип кнопки меню `commands` и наличие аватара, если он передан. Точные пиксели изображения не сравниваются. Скрипт не вызывает `sendMessage` и не рассылает уведомления; работающий worker напоминаний действует независимо.

Изменение файлов само по себе не публикует профиль. При сетевом сбое часть настроек уже может быть применена; сначала проверьте результат. Скрипт не обещает атомарную замену всех полей профиля. Локальная проверка аватара ограничивается сигнатурой JPEG и размером файла; принятие изображения подтверждается Telegram при применении.

Источники: [создание бота и обращение с токеном](https://core.telegram.org/bots/tutorial#obtain-your-bot-token), [команды и режим приватности в группах](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get), [Bot API: getUpdates](https://core.telegram.org/bots/api#getupdates).
