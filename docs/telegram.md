# Telegram Aéza Регулярные платежи

Бот [@aezainkeep_bot](https://t.me/aezainkeep_bot) сохраняет бренд и предоставленный пользователем аватар. Новая роль бота - уведомления в одной корпоративной группе, без финансовых команд, меню расходов и подтверждения оплаты. 25 октября группа «InKeep» подключена человеком через код и web-confirm; Bot API подтвердил две новые отправки. Факты и границы — в qa.md.

## Что получает группа

Напоминание содержит пять элементов:

- имя владельца расхода;
- название платежа;
- сумму;
- валюту;
- плановый срок.

Эти детали видны участникам общей группы. У веб-пользователя при этом личная область: только свои расходы, кроме администратора. Веб-ограничение не скрывает опубликованное уведомление от других участников Telegram-группы. Состав группы контролирует её администратор.

Бот не показывает сводки, список платежей, ближайшие сроки или просрочки по командам. `/summary`, `/payments`, `/upcoming`, `/overdue` и старая навигация финансового меню больше не являются функциями новой версии. Оплата, изменение условий и управление участниками выполняются только через веб-панель и защищённый REST API.

Модуль не проводит банковскую оплату. Введённая отметка - подтверждение участника, а не ответ банка или биллинга Aéza.

## Как подключить корпоративную группу

Нужны администратор приложения и администратор выбранной Telegram-группы. Это могут быть один или разные люди.

1. Администратор приложения входит в веб-панель и генерирует код подключения. Код действует 10 минут.
2. Бота добавляют в корпоративную группу с возможностью отправлять сообщения.
3. Администратор этой Telegram-группы отправляет `/connect@aezainkeep_bot CODE`, заменив `CODE` полученным кодом.
4. Бот проверяет фактический тип чата и статус отправителя в группе. Недостаточно указать ID или название группы в тексте.
5. Найденная группа появляется в веб-панели. Администратор приложения сверяет её и отдельно подтверждает.
6. Только после подтверждения группа становится получателем напоминаний.

Открытие бота по QR, сообщение `/start` и добавление в группу сами по себе доставку не включают. Личная переписка не является допустимой корпоративной группой. Legacy-личный чат не переносится автоматически; прежний `TELEGRAM_CHAT_ID` не обходит процедуру подтверждения.

Код подключения не следует публиковать в другой группе. Одного кода недостаточно для окончательной привязки: обязательны Telegram-проверка и подтверждение в веб-панели. При истечении 10 минут нужно сформировать новый код и пройти актуальную процедуру.

В «Настройки» admin использует GET /api/v1/telegram/connection, POST /connection/request и POST /connection/confirm {request_id} под /api/v1/telegram. DELETE /api/v1/telegram/connection отключает группу. Код действует 10 минут; новый отзывает предыдущий. Group → supergroup требует повторной привязки. При активной sending отключение/замена возвращает 409 до завершения.

## Серверные процессы

API обслуживает веб-панель. `backend.telegram_bot` получает служебную команду подключения и обращается к Bot API для проверки. `backend.worker` отправляет напоминания. Они используют общую SQLite и один серверный токен.

Токен задаётся в закрытом окружении:

```dotenv
TELEGRAM_BOT_TOKEN=собственный_токен_бота
```

Строка выше показывает имя параметра, не рабочее значение. Токен не вставляется в браузер, слайды, публичный репозиторий и клиентские `VITE_*`. Полный URL Bot API тоже содержит токен и не должен попадать в логи.

Локальный запуск всех процессов описан в README. Отдельно можно запустить:

```powershell
# Обработка подключения группы
.\.venv\Scripts\python.exe -m backend.telegram_bot
```

```powershell
# Напоминания
.\.venv\Scripts\python.exe -m backend.worker
```

В Linux используется `.venv/bin/python`. Runner `scripts/run.ps1` запускает оба процесса, флаги `-NoWorker` и `-NoBot` отключают их независимо. Не запускайте одновременно runner и те же процессы вручную.

На один токен должен работать один poller. Lease общей базы не блокирует другое приложение на другом хосте с отдельной SQLite. Перед переносом токена старый poller и worker останавливают. Ручной `getUpdates` параллельно рабочему poller не используется. Приложение не должно самовольно удалять существующий webhook.

## Напоминания и очередь

Worker проверяет неоплаченные активные периоды за три календарных дня до срока. Если расход внесли позже, он попадает в ближайшую проверку. Старый неоплаченный период тоже может требовать напоминания; это не ежедневная рассылка.

Конкретный получатель сохраняется в outbox. Текущая привязка группы не должна молча переадресовывать ранее назначенное сообщение. Перед запуском новой группы оператор проверяет, какие задания ожидают отправки и к какому получателю они относятся. Отключение отменяет pending/retry, sent/unknown и offset сохраняются. Новое назначение получает текущие/будущие обязательства и новые поздние записи, не всю историческую просрочку.

Постоянная очередь и атомарный захват защищают от штатных повторов. Подтверждённая отправка `sent` не повторяется после следующего прохода или перезапуска. Если ответ потерялся после принятия запроса Telegram, результат становится `unknown` без автоматического повтора. Оператор сверяет группу с диагностикой; отсутствие ответа не доказывает недоставку.

`sent` подтверждает ответ Bot API. Это не проверка прочтения и не гарантия push-уведомления всем участникам. Модуль не управляет настройками звука, уведомлений и аккаунтов Telegram.

## Диагностика

Если нового сообщения нет, проверить по порядку:

1. Есть ли подтверждённая группа, а не только код или кандидат.
2. Работает ли worker и есть ли у бота право писать в группу.
3. Принадлежит ли срок окну напоминания, активна ли серия, не отмечен ли период оплаченным.
4. Какое состояние и конкретный получатель записаны в outbox.
5. Не существует ли уже подтверждённый `sent` или неопределённый `unknown`.
6. Доступен ли Telegram по сети с обычной проверкой TLS.

Наличие токена не доказывает привязку или успешную доставку. Статус службы `active` тоже не заменяет проверку сообщения. Не сбрасывайте очередь и не меняйте `unknown` на ожидающую отправку вслепую.

После восстановления старой базы нужно сверить доставки, произошедшие позднее её снимка. Финансовые записи, outbox, привязка группы и offset сохраняются согласованно. Пустая база и новый seed не сохраняют историю старых отправок.

## Профиль и команды

Аватар `assets/telegram/avatar.jpg` сохраняется: это предоставленный пользователем JPEG. Происхождение указано в `assets/telegram/provenance.md`. Смена названия не требует перерисовки или генерации изображения.

Новый профиль должен объяснять подключение корпоративной группы и роль уведомлений. Команды допускают служебное подключение и справку; финансовых списков и кнопки «Оплачено» нет. Реальный профиль опубликован и перечитан: start/help, для администраторов групп также connect. Старые финансовые scopes, включая прежний личный чат, удалены и проверены.

`scripts/configure_telegram.py` публикует профиль отдельно от запуска приложения. Скрипт и четыре целевые проверки обновлены под новый профиль; прежний набор семи финансовых команд не публикуется. Проверка username и readback обязательны перед утверждением результата. Публикация профиля не подключает группу и не подтверждает фактическую доставку.

Исторические сведения 24 октября о трёх доставках и семи командах относятся к старой версии. Они не являются приёмкой нового группового сценария.
