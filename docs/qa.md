# Проверка командной версии 25 октября 2026

Продукт: Aéza · Регулярные платежи. Стенд: [https://138.124.14.93/](https://138.124.14.93/). Бот: [@aezainkeep_bot](https://t.me/aezainkeep_bot).

## Что проверено в новой версии

- Windows: `pytest backend/tests qa/test_api.py` — **154 passed**, 135,89 с; одно известное предупреждение Starlette о тестовом клиенте.
- Ubuntu, Python 3.14: тот же новый серверный набор — **154 passed**, 17,65 с.
- TypeScript и production-сборка Vite прошли.
- Настройка нового профиля и четыре целевые проверки скрипта профиля прошли. Эти отдельные проверки не прибавляются к 154 как число уникальных сценариев.

Набор проверяет владельцев и роли, недоступность чужих записей, создание себе/за участника, приглашения и одноразовое принятие, смену пароля с отзывом сессий, неизменяемый env-admin, периоды, даты, деньги и групповую очередь. Тесты Telegram используют управляемый транспорт: это проверка логики, а не подтверждение реального сообщения в новой группе.

## Миграция и сервер

Пробная миграция копии действующей базы прошла. При финальном применении командной версии на сервере сохранены **8 серий, 21 период, 5 outbox-записей sent и offset Telegram-poller**. Идентификаторы, финансовые значения, даты и отметки сохранены, проверки integrity и foreign keys прошли.

После применения HTTPS health отвечает, три службы API/worker/bot активны. Legacy-личный чат не стал подключённой группой. Пять сохранённых sent относятся к предыдущим доставкам; они не являются пятью доставками новой версии.

Сервисы работают от непривилегированного пользователя, API слушает внутренний loopback, наружу опубликован nginx с HTTPS. Технические имена aeza-renewals сохранены для совместимости. Закрытые окружение, база и резервные копии не включаются в публичную поставку.

## Профиль Telegram

Реальный профиль @aezainkeep_bot опубликован и проверен обратным чтением Bot API. Набор содержит **start, help, connect**: обычные области показывают start/help, область администраторов групп — все три. Старые финансовые команды в прежних chat-scopes удалены и результат перечитан. Предоставленный пользователем аватар сохранён.

В новой версии нет /summary, /payments, /upcoming, /overdue, финансовых callback и подтверждения оплаты через Telegram.

## Проверка интерфейса

В локальной браузерной проверке на отдельной синтетической базе выполнены: создание admin с владельцем demo, создание и inspect приглашения, личная область user, поля смены пароля, мастер Telegram с кандидатом и подтверждением. Telegram-кандидат в этом сценарии имитировался, а не поступил из реальной корпоративной группы.

Проверена мобильная ширина 375 px: clientWidth и scrollWidth равны 375, горизонтального переполнения страницы нет. Рабочая область тёмная с нейтральными серыми панелями. Иконка самолётика Telegram белая — RGB 255/255/255. Веб-права дополнены автоматическими API-проверками, а не только наличием/отсутствием кнопок.

## Реальная группа и внешняя проверка

Администратор Telegram-группы «InKeep» выполнил connect с кодом; бот нашёл кандидата, человек подтвердил его в веб-панели. Bot API затем подтвердил **две новые отправки в эту группу**. После финального перезапуска в outbox семь sent: пять прежних и две новые, без повторной рассылки. Прочтение каждым участником не проверяется и не заявляется.

Финальный релиз /opt/aeza-renewals/releases/20261025-team-2: HTTPS health и три службы активны, integrity/FK в порядке. Внешний verifier завершился exit 0, ok:true за 5,50 с: вход, чтение разрешённой области и foreign PATCH с пустым JSON →404. Финансовых изменений verifier не выполнял. На стенде admin видит 8 серий/21 период, legacy-user — 0 собственных; положительные CRUD-сценарии user проверены тестами и локальной синтетической базой.

Это подтверждение работоспособности, а не заявление о состоявшемся выступлении. Семь действий защиты всё равно выполняются вживую.

## Исторические проверки

Прежний релиз 24 октября имел 130 полных серверных тестов и последующие 63 целевые проверки финансового Telegram-меню. У него проверялись общие веб-списки, один заданный чат и команды просмотра. Эти результаты остаются историей проекта и **не приписываются** новой модели владельцев, приглашений и групп.

Тогда также были проверены TLS, HTTP 308, HSTS, Secure/HttpOnly/SameSite-cookie, закрытый анонимный доступ, CSRF/Origin и старый RBAC. Новый серверный релиз отдельно проверен перечисленными выше 154 сценариями и HTTPS health; исторический внешний отчёт не объявляется новым полным внешним прогоном.
