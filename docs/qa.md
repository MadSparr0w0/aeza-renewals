## Внешняя проверка сервера

HTTPS проверен с клиентского компьютера с обычной проверкой сертификата. HTTP возвращает 308 на HTTPS. Cookie содержит Secure, HttpOnly и SameSite=Strict, включён HSTS. Анонимный доступ к данным, Swagger и OpenAPI возвращает 401. Изменения без CSRF или с чужим Origin возвращают 403. Обычный пользователь получает 403 на административные маршруты. Повторная внешняя проверка `.cache/verify-remote.py` после финального развёртывания снова прошла: HTTP 308 → HTTPS, HSTS, закрытый анонимный доступ, RBAC, CSRF и Origin.

API, worker и bot работают отдельными systemd-службами от `aeza-renewals`. Код принадлежит root и доступен службам только для чтения; API слушает 127.0.0.1:8000. Внешний трафик принимает nginx. Закрытый EnvironmentFile имеет права 0600, каталог данных — 0700. Проверка `systemd-analyze verify` прошла; сообщения о CPUAccounting относятся к штатным xfs-службам Ubuntu.

Рабочий релиз: `/opt/aeza-renewals/releases/20261024-2`; `/opt/aeza-renewals/current` — ссылка на него. Полированная версия сайта и обновлённый бот развёрнуты успешно. Все три службы API, worker и bot активны; после перезапуска данные и состояния доставок сохранены. Certbot 5.8 выпустил публичный сертификат IP; пробное автоматическое продление завершилось успешно.

## Telegram

Имя, оба описания, семь команд для настроенного чата, две публичные команды, меню и аватар нового **@aezainkeep_bot** повторно опубликованы после правок и проверены чтением Bot API; все семь команд подтверждены. JPEG — точная копия предоставленного пользователем `aeza.jpg`; источник и SHA-256 приведены в `assets/telegram/provenance.md`.

На сервере подтверждены **три доставки** демонапоминаний (`sent`, без ошибок) и ответы на команды. После перезапуска подтверждённые доставки не повторились. Одновременно активен один lease для нового токена. Старые локальные worker и poller остановлены. Финансовая демобаза содержит шесть инфраструктурных серий с условными суммами; это не тарифы провайдера. Прежняя локальная база сохранена отдельно. Старый outbox не переносился в новую финансовую базу.

DNS-адрес Telegram был недоступен с этого VPS. Для тестового стенда настроен временный адрес API через `/etc/hosts`, с действительной проверкой сертификата `api.telegram.org`. Подробности и порядок сопровождения приведены в `deployment.md`. Worker использует один HTTP-клиент и повторяет только установление соединения до отправки; read/write timeout и неопределённый ответ остаются `unknown` без автоматического повтора.

## Интерфейс

Выполнено прямое визуальное сравнение с авторизованным кабинетом my.aeza.ru: карточки #1f1f1f, радиус 8 px, спокойный переход фона 0,3 с, контурные серверы, изменение размеров окружностей хранилища и клавиши доменов. В модуле эти карточки открывают форму ручного учёта с названием; стоимость не подставляется.

Проверены компьютер и ширина 390 px: календарь списком, карточки продлений, формы, меню, Escape, восстановление раздела, права пользователя и администратора. Убраны запрошенные декоративные подписи; линии сохранены с оранжевым акцентом. Навигация и кнопки не выделяются, данные услуг доступны для копирования. Бирюзовый `::selection` удалён, фокус поля — одна тонкая оранжевая рамка. Горизонтального переполнения страницы и бокового меню нет.

Все активные frontend-акценты приведены к оранжевому `#E97C35`: действия, ссылки, фокус, состояния и акцентные линии. Повторяющиеся notices в настройках, формах, таблице пользователей, подвале списка и навигации убраны; пояснения фактической даты и начала новых условий сохранены.

Доли оплаты используют реальные итоги выбранной валюты. Анимации учитывают `prefers-reduced-motion`; бесконечного декоративного движения нет. Статусы реального VPS и баланс биллинга модуль не запрашивает.

Архив исходников собирается `scripts/package.py`; исключены `.env`, `data`, кэши, локальные виртуальные окружения и зависимости. Перед передачей архив проверяется по реальным значениям локальных секретов.
